# v1: Git-Native Handoff Workflows

Goal: Promem can be used in real assistant-assisted development sessions
without requiring users to manually write JSON.

## Deliverables

- Upward `.promem/` discovery so non-init commands work from any subdirectory
  in a repository.
- Structured Markdown handoff parser for assistant-distilled session summaries.
- `promem save <feature> --from <file>`.
- `promem save <feature> --stdin`.
- `promem import handoff <file> --feature <feature>`.
- Assistant usage docs for Codex, Claude Code, Cursor, and generic assistants.
- `promem snapshot <feature> --dry-run`.
- Improved human-readable snapshot output with branch, changed files, recent
  commits, TODO/FIXME comments, warnings, and existing feature memory.
- Stable `--json` output for snapshot data.

## Handoff Format

Assistants should distill sessions into structured Markdown like:

```md
# Authentication

## Summary
Authentication uses JWT access tokens and refresh token rotation.

## Current State
- Email login is implemented.
- MFA is pending.

## Decisions
### Use refresh token rotation
Reason: limits the lifetime of stolen refresh tokens.
Status: accepted

## TODOs
- Add MFA enrollment.

## Open Questions
- Should refresh tokens be device-scoped?
```

Promem should parse that into the existing memory model and write durable
Markdown under `.promem/features/<feature>/`.

## Commands

```bash
promem save authentication --from auth-handoff.md
cat auth-handoff.md | promem save authentication --stdin
promem save authentication --from auth-handoff.md --json
promem import handoff conversation.md --feature product-direction
promem import handoff conversation.md --feature product-direction --json
promem snapshot authentication --dry-run
promem snapshot authentication --dry-run --json
```

## JSON Contracts

The existing `MemoryInput` contract remains the source of truth. Handoff
Markdown is an input format that must be parsed into `MemoryInput`, then saved
through the same core rendering path as `promem save-json`.

Markdown mapping:

- `# Title` maps to `MemoryInput.title`.
- `## Summary` maps to `MemoryInput.summary`.
- `## Current State` bullets map to `current_state.implemented` by default.
- `### Implemented` and `### Pending` under `## Current State` map to their
  matching current-state arrays.
- `## Decisions` with `### Decision title` maps to `decisions[]`.
- `Reason:` maps to `Decision.reason`.
- `Status:` maps to `Decision.status`.
- `Tradeoffs:` bullets map to `Decision.tradeoffs`.
- `## API` maps to `api[]` when entries include method/path-style headings.
- `## Data Model` maps to `data_model[]`.
- `## Files` maps to `files[]`.
- `## TODOs` maps to `todos[]`.
- `## Open Questions` maps to `open_questions[]`.
- `## Future Work` maps to `future_work[]`.
- `## Prompts` maps to `prompts[]`.

`save --from`, `save --stdin`, and `import handoff` should all support `--json`
with the same response shape:

```json
{
  "feature": "authentication",
  "title": "Authentication",
  "files_written": [
    ".promem/features/authentication/context.md",
    ".promem/features/authentication/decisions.md",
    ".promem/features/authentication/todos.md",
    ".promem/index.json"
  ],
  "warnings": []
}
```

Parsing errors should be human-readable by default and machine-readable when
`--json` is passed.

## Success Criteria

- A developer or assistant can save useful session memory without creating a
  `MemoryInput` JSON file by hand.
- Commands work from nested repo folders and write to the correct `.promem/`
  root.
- Handoff import uses the same core rendering path as `save-json`.
- Assistant docs make the "save this session to Promem" workflow explicit.
- Snapshot output is useful as handoff input and remains machine-readable with
  `--json`.
- Unit and binary integration tests cover save/import handoff behavior and
  upward repo discovery.

## Out Of Scope

- AI-generated memory.
- AI provider extraction from raw transcripts.
- MCP server.
- Semantic search.
- `--git-add`.
- Automatic commits.
- Raw transcript storage.
