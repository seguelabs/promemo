# v1: Git-Native Handoff Workflows

Goal: Promemo can be used in real assistant-assisted development sessions
without requiring users to manually write JSON.

## Status

Implemented.

v1 ships the handoff workflow, upward repo discovery, snapshot JSON, improved
human-readable snapshots, assistant usage docs, and a round-trip-friendly
canonical feature memory file.

## Deliverables

- [x] Upward `.promemo/` discovery so non-init commands work from any subdirectory
  in a repository.
- [x] Structured Markdown handoff parser for assistant-distilled session
  summaries.
- [x] `promemo save <feature> --from <file>`.
- [x] `promemo save <feature> --stdin`.
- [x] `promemo import handoff <file> --feature <feature>`.
- [x] Assistant usage docs for Codex, Claude Code, Cursor, and generic
  assistants.
- [x] `promemo snapshot <feature> --dry-run`.
- [x] Improved human-readable snapshot output with branch, changed files, recent
  commits, TODO/FIXME comments, warnings, and existing feature memory.
- [x] Stable `--json` output for snapshot data.
- [x] Canonical `.promemo/features/<feature>/memory.md` rendering with tolerant
  Markdown parsing for reasonable human edits.

## Handoff Format

Assistants should distill sessions into structured Markdown like:

```md
# Authentication

## Summary
Authentication uses JWT access tokens and refresh token rotation.

## Current State
- Email login is implemented.
- MFA is pending.

## Decisions
### Use refresh token rotation
Reason: limits the lifetime of stolen refresh tokens.
Status: accepted

## TODOs
- Add MFA enrollment.

## Open Questions
- Should refresh tokens be device-scoped?
```

Promemo should parse that into the existing memory model and write durable
Markdown under `.promemo/features/<feature>/`.

## Commands

```bash
promemo save authentication --from auth-handoff.md
cat auth-handoff.md | promemo save authentication --stdin
promemo save authentication --from auth-handoff.md --json
promemo import handoff conversation.md --feature product-direction
promemo import handoff conversation.md --feature product-direction --json
promemo snapshot authentication --dry-run
promemo snapshot authentication --dry-run --json
```

## JSON Contracts

The existing `MemoryInput` contract remains the source of truth. Handoff
Markdown is an input format that must be parsed into `MemoryInput`, then saved
through the same core rendering path as `promemo save-json`.

Markdown mapping:

- `# Title` maps to `MemoryInput.title`.
- `## Summary` maps to `MemoryInput.summary`.
- `## Current State` bullets map to `current_state.implemented` by default.
- `### Implemented` and `### Pending` under `## Current State` map to their
  matching current-state arrays.
- `## Decisions` with `### Decision title` maps to `decisions[]`.
- `Reason:` maps to `Decision.reason`.
- `Status:` maps to `Decision.status`.
- `Tradeoffs:` bullets map to `Decision.tradeoffs`.
- `## API` maps to `api[]` when entries use bullets like
  `- GET /path: Description`.
- `## Data Model` maps to `data_model[]` when entries use bullets like
  `- table_name: Description`.
- `## Files` maps to `files[]`.
- `## TODOs` maps to `todos[]`.
- `## Open Questions` maps to `open_questions[]`.
- `## Future Work` maps to `future_work[]`.
- `## Prompts` maps to `prompts[]`.

`save --from`, `save --stdin`, and `import handoff` should all support `--json`
with the same response shape:

```json
{
  "feature": "authentication",
  "title": "Authentication",
  "files_written": [
    ".promemo/features/authentication/context.md",
    ".promemo/features/authentication/decisions.md",
    ".promemo/features/authentication/todos.md",
    ".promemo/index.json"
  ],
  "warnings": []
}
```

Parsing errors are human-readable through the CLI error path. Machine-readable
error envelopes for failed `--json` commands are deferred to v3, where MCP and
automation clients need a stable CLI-wide error contract.

## Success Criteria

- [x] A developer or assistant can save useful session memory without creating a
  `MemoryInput` JSON file by hand.
- [x] Commands work from nested repo folders and write to the correct `.promemo/`
  root.
- [x] Handoff import uses the same core rendering path as `save-json`.
- [x] Assistant docs make the "save this session to Promemo" workflow explicit.
- [x] Snapshot output is useful as handoff input and remains machine-readable with
  `--json`.
- [x] Unit and binary integration tests cover save/import handoff behavior and
  upward repo discovery.

## Out Of Scope

- AI-generated memory.
- AI provider extraction from raw transcripts.
- MCP server.
- Semantic search.
- `--git-add`.
- Automatic commits.
- Raw transcript storage.
