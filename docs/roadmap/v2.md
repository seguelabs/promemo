# v2: Extraction, Provider Automation, And CLI UX

Goal: Promemo can extract structured memory from notes, handoffs, and snapshots
using a configured provider, while making core CLI workflows self-explanatory,
confirmable, and hard to misuse.

## Status

Partially implemented.

- v2.1 CLI UX is built.
- v2.2 review-before-save dry runs are built.
- v2.3 provider automation is reserved for the next v2 pass.

## Built In v2.1: CLI UX

- Human-readable success output for `save-json`, `save`, and `import handoff`.
- Save/import output reports the parsed title, normalized feature slug, planned
  or written paths, warnings, and suggested next commands.
- `promemo search <query>` prints a clear no-results message in human mode when
  no memory matches.
- `promemo open <feature>` opens the feature memory folder in the user's default
  file browser when available.
- Save/import output consistently points users to
  `.promemo/features/<feature>/` and shows how to view memory files with commands
  such as `less` and `open`.

## Built In v2.2: Review Before Save

- `promemo save-json <feature> --dry-run` parses input and previews the save
  report without writing files.
- `promemo save <feature> --from <file> --dry-run` previews parsed handoff memory
  without writing files.
- `promemo import handoff <file> --feature <feature> --dry-run` previews imported
  handoff memory without writing files.
- Dry-run reports include the same next-step guidance as successful saves, while
  clearly saying no files were written.

## Reserved For v2.3: Provider Automation

- Provider trait.
- OpenAI-compatible provider.
- Config loading from `.promemo/config.toml`.
- Command that turns unstructured notes, handoffs, or snapshots into
  `MemoryInput` JSON using a configured provider.
- Optional local provider path after the OpenAI-compatible path is stable.
- Review-before-save flow for provider-generated memory that shows what will be
  parsed, where it will be saved, and what files will change before writing.

## CLI UX Examples

Successful save/import in human mode should be explicit:

```txt
Parsed handoff: Promemo Website Handoff
Saved feature: aun
Wrote 9 files under .promemo/features/aun/

Next:
  promemo load aun
  promemo search "keyword"
  promemo open aun
```

Empty search should not look like a broken command:

```txt
No memory found for "refund retry".
```

After saving, Promemo should guide users toward opening files rather than
accidentally trying to execute Markdown paths in the shell:

```txt
View memory:
  less .promemo/features/aun/memory.md
  open .promemo/features/aun
```

## Success Criteria

- [x] A successful save/import gives the user enough feedback to know what happened
  and what to do next.
- [x] Empty search results are explicit in human mode.
- [x] Users can open a saved feature folder without knowing hidden `.promemo` layout
  details.
- [x] Common terminal mistakes, such as trying to execute a Markdown path, are
  addressed through suggested commands in output and docs.
- [ ] Promemo can produce useful structured memory from unstructured notes.
- [x] Raw handoff text and transcripts are not stored.
- [ ] Provider output maps into the same JSON contract used by `save-json`.

## Out Of Scope

- MCP server.
- Hosted team mode.
- Provider-specific UI.
- Stable machine-readable error envelopes for failed `--json` commands.
